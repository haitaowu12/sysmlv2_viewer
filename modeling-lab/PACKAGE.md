# SysML v2 skill package

This directory is the portable, maintained runtime for the SysML modeling specialist. It owns its instructions, executable reference workbench, examples, contracts and tests. It has no runtime dependency on a notebook, product checkout or Downloads folder. The former product audit is provenance, not an executable prerequisite.

`python3 scripts/sysml.py doctor` checks the package, Python, Java, Graphviz and the pinned language engine. `setup --archive <official-kernel.zip>` installs the engine privately under `.runtime/`; no Jupyter kernel or machine settings are changed. Runtime binaries and optional test dependencies are ignored by Git. The local transfer bundle includes the runtime and original license files. Python 3.10+, Java 21+ and Graphviz must be available on the destination system.

The reference engine, UI and agent workflows are a bounded capability. Static checks do not establish full language/notation conformance, source entailment, simulation, engineering approval or commissioning readiness. Source editing in the browser remains draft-only. The separate `evolution` command supports witnessed impact, blocked procedure planning and exact-base local promotion; promotion currently requires POSIX locking on macOS/Linux. Windows promotion is explicitly rejected, and clean-machine portability is not established by same-host relocation. The product's production bridge and external lifecycle services are not included or claimed.

The October 14 first Lab workflow adds explicit project-file save/reopen, brief/decision notes, validated bounded engineering proposals with review/undo, and an offline HTML reader export. It never overwrites the supplied model file. Project files are limited to 8 MiB, individual source/baseline text to 512 KiB, and recipes to the supported local rendering profile. Source-set import retains up to 64 original files and their paths within the same 512 KiB assembled source limit. The single-process service retains the latest model for exact-base editing; concurrent tabs must revalidate after another tab changes that state. There is no shared repository, automatic persistence, external requirements synchronization or authenticated approval. Large-model experiments do not remove the existing 2000-occurrence, 40-node/120-relation diagram and 40-by-40 matrix limits.

Implementation was consolidated from the owned `sysml-v2-reaudit` development snapshot on 2026-10-04. Methods were adapted independently from Arcadia, EasyMOD, SysON and SysModeler as cited in the method reference. The browser view workspace separately reuses the pinned OpenSysML canvas/layout modules under their retained license and notices; see `references/view-workspace-architecture.md`. Preserve the included source notices and official runtime archive license files. No public publication or runtime redistribution assessment is implied by this local package.

## Maintain or transfer

The `contributor-pilot` fixture supplies an independent two-baseline test for the product contributor workflow. `contributor-check` compares exact managed baseline and candidate reports against frozen expected facts; `contributor-review` renders a self-contained, read-only HTML review from those reports. Both commands expose `--help` through `scripts/sysml.py`. Review export retains the original historical observation, discloses its changed applicability and leaves candidate acceptance unrecorded. These commands do not mutate the product, replace its command service or establish runtime equivalence with the separate product engine.

Maintain this folder as the source of the reference capability. Do not also patch the former audit copy. After deliberate code/reference changes, run the included tests, then `python3 scripts/package_manifest.py` and `python3 scripts/sysml.py doctor`. The manifest detects missing or changed source files; it is not a signature or approval record.

The maintained source inventory is the exact `SOURCE_PATHS` tuple in `scripts/package_manifest.py`. To add a maintained script, reference, test or fictional fixture, review its contents and dependencies, add its exact package-relative POSIX path to that tuple, then regenerate the manifest. Regeneration hashes only registered files and fails for missing files, unsafe paths or symlinks. It never discovers or adopts adjacent files. Doctor requires the manifest inventory to match the registration exactly. The original runtime license hashes are pinned separately in `scripts/sysml.py`; an engine upgrade requires deliberate review of those license hashes and `workbench/config/reference-pilot-lock.json`.

Create a local transfer with `python3 scripts/sysml.py bundle --output /destination/sysml-v2-modeling.zip`. Extract it anywhere and run its `scripts/sysml.py doctor` from any current directory. The bundle includes exactly the registered maintained sources, their integrity manifest, the locked engine JAR, the hash-matching `.sysml`/`.kerml` library sources and the pinned original `LICENSE`/`LICENSE-GPL` files. Each exported file is checked again while writing. Runtime installer/Jupyter files are unnecessary for this entry point and are excluded.

Unregistered files are excluded even when doctor passes: credentials, repository metadata, client inputs, generated model outputs, caches and dependencies remain outside the transfer. Fictional examples are transferred only through their named registrations. Exporting work products requires a separate explicit export choice; placing them beside the package does not authorize transfer. A source-only Git checkout requires the one-time `setup` step. UI development uses `cd workbench`, `npm ci --ignore-scripts`, then `npm test`; `.npmrc` records the peer-resolution mode used by its lock.

For the current launch, editable study, frozen reader and recovery procedure, use [Local handoff](LOCAL-HANDOFF.md). Fresh-directory and human-review evidence belong to the dated delivery review; this link is not a release qualification.
