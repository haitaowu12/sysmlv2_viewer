## Findings translated into product decisions

1. **Language authority is external to every product.** Official artifacts and Pilot evidence remain visible in capability claims.
2. **One web UI is credible for authors and non-modelers.** Rhapsody SE, Jama, Valispace, VS Code web, and published model views all demonstrate useful browser workflows. Local installation is an OS-capability decision, not a usability tier.
3. **Question-driven projections beat diagram inventories.** Borrow Capella viewpoints, trace/matrix navigation, and VoidAliot view guidance; do not make tabs or diagram count the product taxonomy.
4. **Safe editing resembles IDE refactoring and pull-request review.** Every graphical/property edit gets preview, deterministic checks, semantic diff, and explicit apply.
5. **Engineering governance is a separate product layer.** Jama-style frozen scope, GitHub-like disposition states, commercial-tool trace matrices, and deterministic evidence sit above the language engine.
6. **Properties must expose semantic derivation.** Owned/inherited/derived/default/effective values are distinguished; no flattened form hides origin.
7. **Server-side authorization is mandatory.** Browser reach does not grant local or hosted workspace powers.
8. **Avoid importing donor ontologies.** Arcadia, proprietary property schemas, and requirements-platform databases inform views and workflows but never replace SysML/KerML semantics.

## Method limitations

- Commercial entries are based on vendor documentation and public behavior, not source inspection.
- Vendor “full support” claims are not accepted as conformance evidence.
- Screens, icons, stencils, and proprietary workflows are not copied.
- Phase 1 measures runtime engines independently; this table is not a benchmark result.
