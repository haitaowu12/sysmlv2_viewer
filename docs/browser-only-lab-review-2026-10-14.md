## Ordered completion slices

Pro's **26–42 active-hour total is a planning estimate**, not a commitment or authorization to spend that amount now. Do not turn a first-slice cap into an unlimited project budget. Select one bounded slice at a time, provide a visible checkpoint within 90 minutes and preserve the 30-minute individual / 60-minute combined technical-detour stops.

|---|---|---:|

Human observation is valuable, but Pro's blanket rule to block publication whenever Tony is unavailable is not adopted as a new approval requirement: the user already authorized publication and continued work while unavailable. Missing human evidence limits usability claims; demonstrated technical failures and existing agreed criteria remain the actual gates. Pro's new latency thresholds are proposals, not accepted requirements or achieved results. Reconcile them with the existing fixture/task budgets before measurement; do not silently relax an earlier target.

The immediate next slice is **semantic viability**, followed by transactional recovery before broader workflow qualification. Stop this runtime route if required typed facts/anonymous identity cannot be exposed within the bounded adapter work, or if measured browser resources remain incompatible after a bounded optimization. Name the lost user task before proposing a reduction. A download site or backend cannot silently replace the selected browser-only application.

Defer accounts, shared editing, cloud storage, additional AI features, new diagram frameworks and broad enterprise language coverage. They do not close the agreed workflow.
